# 路飞风格桌面宠物 v1 Spec

## Why
用户希望在 Windows 上拥有一个常驻桌面的宠物，用更低干预的方式自动记录工作中的文本痕迹，并自动总结形成专业日报/周报/月报，同时提供轻量陪伴与激励。

## What Changes
- 新增：基于 Godot 的 Windows 桌面宠物应用（动画状态机：忙碌/休息/睡觉/互动）
- 新增：全局文本采集（剪贴板 + 全局打字事件采集）与本地记忆流水
- 新增：分段自动总结（DeepSeek）并“删原文留精华”的淡忘机制
- 新增：任务管理（待办/完成勾选；完成后可隐藏但保留在记忆中）
- 新增：专业化报表生成（日/周/月/半年），输出风格接近“大厂员工”
- 新增：新闻/热点陪聊（不要求出处链接）
- 新增：用户称呼记忆（记住“操作者是谁/怎么称呼你”）
- 新增：一键安装包（安装向导 + 卸载 + 可选自启；卸载时可勾选是否清除记忆）

## Impact
- Affected specs: 桌宠 UI、动画状态机、全局采集、记忆存储、LLM 调用、报表生成、安装器
- Affected code: 新增独立应用/模块（Godot 工程 + Windows 原生 Helper + 安装器脚本）；不修改现有核心 CLI 逻辑

## ADDED Requirements

### Requirement: Windows 桌面宠物壳
系统 SHALL 提供一个 Windows 桌面宠物应用，可常驻运行，并以动画方式展示状态变化。

#### Scenario: 基本运行
- **WHEN** 用户启动桌宠
- **THEN** 桌宠在桌面显示并进入默认闲置状态

#### Scenario: 忙碌/休息状态切换
- **WHEN** 检测到新的文本事件被写入记忆流水
- **THEN** 桌宠切换到忙碌动画一段时间后回到闲置/休息

### Requirement: 全局文本采集（剪贴板 + 打字）
系统 SHALL 采集用户电脑上的文本相关操作并写入本地记忆流水：
- 剪贴板文本变更（复制/剪切/粘贴产生的文本）
- 全局打字输入产生的文本片段（跨应用）

#### Scenario: 剪贴板采集
- **WHEN** 剪贴板文本发生变化
- **THEN** 系统将文本内容与时间戳写入记忆流水

#### Scenario: 全局打字采集
- **WHEN** 用户在任意应用中输入文字
- **THEN** 系统以片段形式写入记忆流水

#### Constraints
- 全局打字采集存在输入法（IME）导致“最终上屏文本不完全可还原”的风险，v1 允许存在缺口/噪声，但必须保证系统可用并可通过总结机制降低噪声影响。

### Requirement: 记忆流水与淡忘机制（分段总结后删原文）
系统 SHALL 将采集到的原始文本写入“短期原文缓冲区”，并按阈值触发自动总结：
- 触发条件至少包含：按时间阈值或按字数阈值
- 总结成功后，系统 SHALL 删除对应时间段的短期原文，仅保留结构化“精华摘要”

#### Scenario: 自动总结与删原文
- **WHEN** 短期原文缓冲区达到总结触发条件
- **THEN** 系统调用 DeepSeek 生成精华摘要
- **AND** 将精华摘要写入长期记忆
- **AND** 删除该段短期原文

### Requirement: 报表生成（专业模板）
系统 SHALL 基于长期记忆（精华摘要 + 任务事件）生成专业报表：
- 日报、周报、月报、半年报
- 输出 SHALL 使用模板化结构，表达结果导向、条目化、尽量量化；不得无依据编造具体事实

#### Scenario: 生成日报
- **WHEN** 用户请求生成日报
- **THEN** 系统输出符合“今日完成/关键产出/问题风险/明日计划”等结构的专业日报文本

### Requirement: 任务管理（待办/完成）
系统 SHALL 提供任务录入与完成勾选能力：
- 用户可新增待办事项
- 用户可勾选完成
- UI 可隐藏已完成，但数据 SHALL 保留在记忆中供总结/报表使用

#### Scenario: 完成任务但保留记忆
- **WHEN** 用户勾选某待办为完成
- **THEN** UI 中该任务可进入隐藏/折叠状态
- **AND** 任务完成事件与任务内容仍被保留在本地数据中

### Requirement: 新闻/热点陪聊（不要求来源）
系统 SHALL 提供“陪聊为主”的热点话题输出，不强制提供出处链接。

#### Scenario: 主动发起话题
- **WHEN** 桌宠达到随机触发条件且用户处于闲置状态
- **THEN** 桌宠生成一个可聊的话题并向用户发起互动

### Requirement: 情绪安慰/激励（可控且不打扰）
系统 SHALL 能基于近期文本片段进行轻量情绪信号判断，偶尔安慰/激励用户：
- 必须具备冷却时间，避免频繁打扰
- 文案风格贴合“路飞式”人设

#### Scenario: 触发安慰
- **WHEN** 近期文本片段呈现明显负向压力信号且冷却时间已结束
- **THEN** 桌宠输出一条安慰/激励文本

### Requirement: 用户称呼记忆
系统 SHALL 允许用户设置“桌宠称呼用户的方式”，并持久化保存到本地记忆中。

#### Scenario: 首次设置称呼
- **WHEN** 用户在桌宠中设置称呼
- **THEN** 系统保存称呼并在后续对话/报表中可使用该称呼

### Requirement: DeepSeek LLM 接入（单一 Provider）
系统 SHALL 仅提供 DeepSeek 作为 LLM Provider，用于：
- 分段总结与报表生成（Report 模式）
- 新闻/陪聊与情绪关怀（Chat 模式）

#### Scenario: LLM 配置存储
- **WHEN** 用户配置 DeepSeek endpoint / model / key
- **THEN** 系统将配置保存到本地用户配置中，不在代码与日志中输出明文密钥

### Requirement: 安全护栏（暂停/紧急停止/卸载清理）
系统 SHALL 提供以下安全控制：
- 全局采集的一键暂停/恢复
- 紧急停止（停止采集与停止向模型发送内容）
- 卸载时可选择是否清除 AppData 中的记忆数据

#### Scenario: 暂停采集
- **WHEN** 用户触发暂停
- **THEN** 系统立即停止采集并在 UI 上呈现明确状态

#### Scenario: 卸载清理记忆
- **WHEN** 用户卸载并勾选“清除记忆”
- **THEN** 安装器删除 AppData 下的记忆数据目录

### Requirement: Windows 安装包（安装向导 + 卸载 + 可选自启）
系统 SHALL 提供 Windows 一键安装体验：
- 安装时可选择安装目录
- 安装时提供可选“开机自启”（默认不勾选）
- 提供卸载入口

#### Scenario: 选择安装目录
- **WHEN** 用户运行安装包并选择安装目录
- **THEN** 系统安装到用户选择的目录

## MODIFIED Requirements
无。

## REMOVED Requirements
